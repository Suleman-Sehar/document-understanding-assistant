## 2026-10-20
- Switched to explicit openai/gpt-4o-mini to avoid OpenRouter routing to Minimax. The model slug is now pinned in one place (DEFAULT_MODEL in src/dua/llm_extractor.py), mirrored in .env.example (OPENAI_MODEL=openai/gpt-4o-mini) and as the --model CLI default in scripts/run_dev.py; the runner refuses a slug without a provider prefix because OpenRouter auto-routes an unprefixed slug to another provider, which would silently change the model under test. The endpoint defaults to OPENAI_BASE_URL or https://openrouter.ai/api/v1.
- Model pinning changes the cache key (prompt version + model + document text). Responses produced by one model can no longer be served for another model, and the model id returned by the API (_served_model) is recorded in the cache payload and in evidence/debug_<doc_id>.json, so the model that answered each document can be audited. Consequence: the 96 cached responses of the 10:03-10:10 dev run do not record a model, so the model that served them cannot be proven from the artifacts; the dev run has to be repeated with the pinned model before the numbers are reportable.
- Verified with no spend: scripts/check_model_routing.py prints the exact request that would be sent (model=openai/gpt-4o-mini, base_url=https://openrouter.ai/api/v1, OPENAI_API_KEY set) with the client mocked, and the free OpenRouter /models endpoint resolves openai/gpt-4o-mini to "OpenAI: GPT-4o-mini" (provider openai).
- Test isolation: tests/ deleted the repository cache/ directory (shutil.rmtree("cache")), which would have destroyed the paid run responses. tests/conftest.py now redirects CACHE_DIR and DEBUG_DIR to a temp directory for every test; the destructive rmtree calls were removed. 20 tests pass.
- 100-doc dev run with the pinned model: smoke test on doc_0001 confirmed OpenRouter served the model id "openai/gpt-4o-mini" (not Minimax), so the run was started. The run stopped after 47 documents because the OpenRouter account hit its credit limit: GET /api/v1/credits reports total_credits 0 with total_usage $0.19656653. The remaining 48 documents failed all three attempts with 402 and fell back to the rules baseline; 4 empty documents were skipped without an API call. No crash, no partial cache entry.
- New error type: OpenRouter 402 (credit / in-flight budget exhausted). The in-flight variant is recoverable - 24 documents retried once and succeeded, and 0 documents needed a schema-validation retry. The credit-exhaustion variant exhausts the three attempts and falls back to rules. Documented in docs/error_analysis.md.
- Partial dev results (51/100 documents evaluated, 47 LLM calls, $0.010980, avg latency 3.83s): evidence/dev100_eval_2026-10-20_partial48.txt, evidence/run_dev100_2026-10-20.json, evidence/dev100_run_2026-10-20.log. The LLM extractor beats the frozen rules baseline on every field that has support; 280/286 (97.9%) of the labelled values that are actually present in the document body were extracted correctly.
- Cache hardening: the cache write is atomic (temp file plus replace) and a corrupt entry is now a cache miss instead of an exception that aborted the run (one corrupt entry was found, doc_0015, and removed).
- Blocker: the 49 documents without a cached output need roughly $0.011 of OpenRouter credit. The run resumes from the cache, so only those documents are paid for again.
